IBD dataset

Gegevensset voor volwassen patiënten met inflammatoire darmziekten (IBD): scopieën en calprotectinemetingen, plus alcoholgebruik.

Version 0.1.0 · definition: ibd-dataset · generated: Group, Parameters

Cohort

Alle patiënten van 18 jaar of ouder op het moment van aanleveren met een actief, regulier DBC-zorgtraject (zorgtype 11 of 21) dat op of na 01-01-2018 is geopend en waarvan de specialisme-diagnose bij IBD hoort. De startdatum 01-01-2018 is bewust niet dynamisch.

A patient is in the Group when every criterion below is satisfied. Each criterion becomes one bulk-data member-filter modifier extension on the Group; the Bulk Data IG defines several filters as all of them having to match.

Post-query filters

  • A calprotectin measurement counts only when it falls within the 90 days up to and including the start of a scopie of the same patient. A date relation between two resources cannot be expressed in a FHIR search.
    • Observation.effective >= Procedure.performed.start - 90 days and Observation.effective <= Procedure.performed.start and Observation.subject = Procedure.subject

Every _typeFilter and every element above must be covered by the de-identification ruleset, see De-identification.

Request sequence

The export is a sequence of ordinary FHIR requests, executed in this order by the client. They cannot be combined in one Bundle: $export is asynchronous and a transaction cannot wait for a Group that is created asynchronously. Fill in every {placeholder} in the Group and the Parameters first.

  1. Create the cohort Group. PUT [base]/Group/ibd-dataset-cohort with the Group. A PUT fixes the id, so step 3 does not need to read it from a response. A server that creates the Group asynchronously (Bulk Cohort) answers with a status location; poll it until it is complete.
  2. Wait for the Group. Continue only when the Group exists and its members are resolved.
  3. Start the export. POST [base]/Group/ibd-dataset-cohort/$export with header Prefer: respond-async and the Parameters as body. The answer is a status location.
  4. Wait for the export. Poll the status location until it returns the manifest.
  5. Download the files listed in the manifest.

How the de-identification ruleset reaches the server is not part of the Bulk Data specification and is not decided here.
